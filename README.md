# plasma-biological-staging

Analysis code for *Plasma proteomics reveals stage-dependent biological remodelling in Alzheimer's disease*: a plasma biological staging framework (Stages 0 to 4) built from BD-p-tau217 (T1) and eMTBR-tau (T2) in the K-ROAD cohort, with external validation in PITT-ADRC.

| Directory | Language | Content |
|---|---|---|
| `kroad/` | Python | Marker selection and threshold derivation, stage assignment, clinical and longitudinal validation, proteome-wide analyses (Figures 2 to 4, Supplementary Tables 1 to 5) |
| `pittsburgh/` | R | External validation in PITT-ADRC (Figure 5, Supplementary Table 6) |
| `figure5/` | Python | Figure 5 assembly from the aggregate results returned by the PITT-ADRC team |

Fixed thresholds (log2 NPQ): T1 positive if BD-p-tau217 >= 9.562758948; eMTBR-tau 9.735217224 / 10.35845619 / 11.60847036 separate Stages 1, 2, 3 and 4; T1-negative/T2-positive profiles are unstageable. `kroad/src/biological_staging/staging.py` and `pittsburgh/validation_common.R` implement the same rule.

## 1. System requirements

- Operating system: tested on Windows 11 (x64) and Ubuntu 24.04 (x64). Any OS with Python and R should work.
- Python 3.12 or 3.13 with the packages pinned in `requirements.txt`: numpy 2.5.4, pandas 3.0.6, scipy 1.18.1, statsmodels 0.15.0, scikit-learn 1.9.1, matplotlib 3.11.2, openpyxl 3.1.5, pytest 9.1.1. Tested with Python 3.12.14 (Windows 11) and Python 3.13.16 (Ubuntu 24.04).
- R 4.3 or later with `MASS` and `nlme`, both included in a standard R installation. Tested with R 4.5.2 (MASS 7.3-65, nlme 3.1-168) on Windows 11 and R 4.3.3 (MASS 7.3-60, nlme 3.1-164) on Ubuntu 24.04.
- No non-standard hardware. A desktop computer with 8 GB RAM is sufficient.

## 2. Installation

```sh
git clone https://github.com/SMC-Dementia/plasma-biological-staging.git
cd plasma-biological-staging
python -m venv .venv
source .venv/bin/activate        # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m pytest kroad/tests -q  # 7 tests
```

R is installed from https://cran.r-project.org; nothing else is needed for the R scripts. Installing the Python packages takes about a minute on a desktop computer.

## 3. Demo

Both demos use synthetic data generated by the scripts in the `demo/` directories. They check that the code runs and show the output format; they do not reproduce the manuscript values.

### K-ROAD analyses

```sh
python kroad/run_all.py --data-dir kroad/demo/inputs --outdir demo_outputs/kroad --demo --figures
```

Input: 150 synthetic participants (30 per stage), 600 clinical assessments, 450 serial draws, 197 non-tau proteins and a tau PET table (`kroad/demo/inputs/`, regenerated with `python kroad/demo/generate_demo.py kroad/demo/inputs`). `--demo` reduces bootstrap replicates to 30.

Output: `demo_outputs/kroad/tables/` (CSV tables named after the manuscript items, for example `Supplementary_Table_S4_stage_associated_34.csv`, `Figure3B_transition_summary.csv`), `demo_outputs/kroad/figures/` (component plots), one log per script and `execution.json` with run times. A reference copy of the tables and figures is in `kroad/demo/expected_output/`.

Run time: a few minutes on a desktop computer. Mixed-model standard errors in the demo tables may differ slightly between platforms.

### PITT-ADRC analyses

```sh
python pittsburgh/run_pittsburgh.py --input pittsburgh/demo/synthetic_plasma.csv --clinical pittsburgh/demo/synthetic_mmse.csv --outdir demo_outputs/pittsburgh
```

Input: 300 synthetic participants with 1,200 MMSE assessments (`pittsburgh/demo/`, regenerated with `python pittsburgh/demo/generate_synthetic.py`).

Output: `Fig5A_*`, `Fig5B_*`, `Fig5C_*` CSV tables and figures, `T1_cutoff_and_stage_counts.csv`, model summaries, `run_summary.json`. A reference copy is in `pittsburgh/demo/expected_output/`.

Run time: a few seconds.

## 4. Instructions for use

### K-ROAD analyses

`kroad/run_all.py` takes a directory with five CSV files in the canonical schema (`kroad/metadata/schema_template.csv`): `baseline.csv` (one row per participant at baseline), `serial.csv` (one row per blood draw), `clinical.csv` and `coupling_clinical.csv` (one row per CDR-SB assessment) and `tau.csv` (baseline participants with tau PET). Analyte columns hold phase/batch-adjusted log2 NPQ values. `kroad/scripts/prepare_kroad_inputs.py` maps the K-ROAD database export files to this schema.

```sh
python kroad/scripts/prepare_kroad_inputs.py --baseline <baseline.csv> --serial <serial.csv> --clinical <clinical.csv> --coupling <coupling.csv> --tau-workbook <tau_pet.xlsx> --out <input_dir>
python kroad/run_all.py --data-dir <input_dir> --outdir <output_dir> --figures
```

Without `--demo`, the run ends with `kroad/scripts/99_reproducibility_QC.py`, which compares the outputs with the manuscript values stored in `kroad/reference/reference_results.json` and writes `QC_REPORT.csv`. On the K-ROAD data all checks pass. Each script can also be run on its own; `--help` lists its arguments.

Shared code is in `kroad/src/biological_staging/`: `config.py` (thresholds, column names, reference counts), `staging.py` (stage assignment, tau PET hierarchy, transition labels), `models.py` (OLS, HC3 and mixed models), `stats.py` (bootstrap, Youden cutoff, BH-FDR, contrasts). `kroad/metadata/` lists the 197 screened non-tau proteins, the 34 stage-associated proteins with their domains and K-ROAD coefficients, and the T1/T2 candidate markers.

### PITT-ADRC analyses

```sh
python pittsburgh/run_pittsburgh.py --input <plasma.csv> --clinical <mmse.csv> --outdir <output_dir>
```

Input columns and outputs are described in `pittsburgh/README.md`. The aggregate results returned by the PITT-ADRC team are in `figure5/source_data/`; `python figure5/build_figure5.py` assembles Figure 5 from them.
